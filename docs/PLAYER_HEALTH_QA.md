## 資料與公開範圍

使用者明確選擇全部沿用既有公開 GitHub 雲端同步。`data/health.json` 位於既有 data 分支，以球員姓名為鍵；未填寫的身高、體重、生日不會推估。身高單位 cm、體重 kg，支援一位小數。打擊側為 U/R/L/S，傳球手為 U/R/L/B；生日為西元 YYYY-MM-DD。年齡使用台北日期，星座為一般日期區間的趣味註記。

除了打擊側，其餘欄位只供紀錄，不影響球員能力評分、打線模型、健康判讀或戰術指標。

新檔案不存在時視為尚未填寫，不會在啟動時自動建立或填入球員個資。使用者儲存後才透過既有三方合併／409 重試寫入器上傳；不同球員的併發修改保留，若兩端改同一球員，沿用既有衝突提示與本機優先規則。

本機 key 為 `rebas_player_health`；失敗待同步編輯另存於 `rebas_player_health_pending`，重開或重新整理仍保留，介面顯示待同步並提供重試。完整 JSON 備份包含健康資料（包括此裝置的待同步版本）。

## 方向定義

- 球場 x < .40 為左側、.40 ≤ x ≤ .60 為中線、x > .60 為右側；座標必須為 0–1 的有效數字。
- 右打：左拉右推；左打：右拉左推；中線不變。
- 優先使用 PA 的實際 `battingSide: R/L`，沒有時才採球員的固定左／右打設定。因此補填習慣會校正沒有逐打席側別的歷史紀錄；已記實際側的打席不會隨習慣變動。歷史編輯可修改側別，或清空為依球員設定。
- 未設定與左右開弓不會被當成右打。沒有實際側別的樣本列為待補，方向百分比只使用已判定的 `direction_n = pull + cent + oppo`。擊球型態、打席、安打、OPS、xBA 等原有計算不變。
- 左右開弓者在即時場記記錄擊球前須指定本打席側別；欄位不會套到下一位打者。保送、三振、跑者出局不需指定擊球側。
- 歷史彙整日誌、個人噴流、全隊噴流、分析頁、比較、排行、自訂圖表與診斷共用規則。無方向資料呈現待補或排除於方向排行，不顯示為實測 0%。
- 球場座標從不鏡射。混合左右打者的守備建議依實際左／中／右落點，而非把所有拉打直接說成左移。
