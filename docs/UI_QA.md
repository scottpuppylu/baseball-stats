## 重現方式

需要 Node.js 與已安裝的 Google Chrome。第一次在專案目錄執行 `npm install`（只安裝測試用的 Playwright，不下載瀏覽器），之後：

```powershell
npm test
```

`tests/run-all.cjs` 先跑全部單元測試，再逐一執行每個瀏覽器測試；每個測試各自啟動全新的隔離預覽伺服器與 Chrome（隨機本機埠），結束即關閉，避免前一個測試的模擬寫入影響下一個。只跑單元測試可用 `npm run test:unit`。

隔離預覽只綁本機，移除實際 credential，雲端寫入改寫到記憶體，不會修改 data/*.json。截圖及 JSON 報告在 `%TEMP%\baseball-ui-qa`，可用 `UI_QA_OUTPUT` 指定其他目錄。單獨執行某個瀏覽器測試時，可手動執行 `node tests/ui-preview-server.cjs`，並以 `UI_PREVIEW_URL`／`UI_CDP_URL` 指定位址。

## 2026/10/10 資料綁定修正

經使用者授權修正既有問題：多處程式只重新指定 `allGames`／`allLogs`，未同步 `window.allGames`／`window.allLogs`，而整季聚合讀的是後者。結果是第一次開啟（或不保存資料的瀏覽器，如 LINE 內建瀏覽器）時場記比賽不計入成績，新比賽要重新整理兩次才出現，手動補登成功後畫面也不會立即更新。

修正方式為以存取器讓 `window.allGames`、`window.allLogs` 永遠指向目前資料（3 行）；完整性檢查將此 3 行還原後仍符合原始雜湊。隔離預覽實測：首次開啟由 0 場／0 筆場記日誌改為 4 場／43 筆，簡承均 PA 由 38 改為 47；手動補登後筆數由不變改為立即 +1。`tests/ui-insights.cjs` 已加入首次開啟與補登即時更新的檢查。

## 2026/10/10 打擊弱點診斷 3.0

經使用者要求升級「球員打擊弱點診斷與技術改善方針」。新模組 `player-diagnostics.js`（唯讀；取代原 `renderDiagnostics`，業務腳本未改，完整性雜湊不變）。

3.0 做法：
- 比較基準一律是本隊同期（以總數計算，不是平均的平均）；隊內百分位只用滿 10 打席的隊員。
